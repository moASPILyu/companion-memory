# companion-memory · 会做梦、会自己纠错的陪伴 AI 记忆

给陪伴型 AI（聊天机器人、虚拟角色、QQ/微信里的 AI 伙伴）用的一套长期记忆：她记下你们说过的每句话，自己写一份《我对他的了解》，每周、每月写回顾；空闲的时候，再把记忆逐句拿回聊天原文对账，记错了自己改——我们叫它**记忆的 dreaming 自纠错机制**。

这套方法在一个真实的陪伴 AI 上跑了一个多月，规矩都是踩坑踩出来的，每条为什么这么做写在 [方法说明](docs/method.md) 里。

- 纯 Node.js，没有任何依赖，不用向量库。在真实聊天上和本地向量模型比过找旧事，效果打平，见 [旧事怎么想起来](#旧事怎么想起来)。
- 模型随便接：传一个 `llm(system, user) => 文字` 的函数就行，自带 OpenAI 兼容接口的适配（DeepSeek、OpenAI、本地模型的兼容接口都能用）。
- 记忆都是能直接打开看、手改的 Markdown 和 JSONL。
- 提示词是中文的。

## 为什么要“对账”

AI 整理记忆时最常犯、也最难发现的错，是**把自己说的话记到你头上**。

> 他：今天走了两万步，腿废了
> AI：走这么远，这趟值了！
> 他：好哦
>
> 笔记：他走再远也说“这趟值了”。 ✗

我们在真实数据上逐句核过：一份 87 句的笔记里有 19 句写错，其中 17 句是这种错。更麻烦的是，笔记每次更新都以上一版为底稿，一句错话能跟着走几十个版本，没有人会回头查。

所以这套记忆把**原始聊天当成唯一的事实来源**，所有整理出来的东西都能、也会定期回去对账：

| | 校对前 | 现在 |
|---|---|---|
| 87 句里判出有错的 | 29 句 | 7 句 |
| 其中“AI 的话算成用户的” | 19 句 | 4 句 |

（真实聊天不公开。仓库里有一套合成数据可以自己复现同类现象，见 [评测](#评测)。）

## 整套怎么工作

```
每句话 ──► 流水账（只追加，唯一事实来源）
              ├─► 原话事实：只从用户的话里逐字摘，近况 30 天过期
              ├─► 《我对他的了解》：AI 第一人称写，带日期，写入前查说话人
              ├─► 《我和他说话的习惯》：每天回看自己怎么回话
              ├─► 周回顾 / 月回顾：写了不改，聊天时按话题翻出一两段
              ├─► 片段回忆：按用户这句话找更早聊过的几段原话
              ├─► 翻记录工具：用户问“上次那个……”时，AI 自己翻聊天原文
              └─► dreaming 自纠错：空闲时逐句对账
                     ├─ 说话人搞反、机械检查也确认 → 自动改
                     ├─ 其他疑点 → 附原文交给下次整理，AI 自己判断改不改
                     └─ 错误类型逐周统计
聊天时：现在几点 + 两份笔记 + 相关回顾 + 旧片段 + 相关原话 ──► 拼在请求末尾
```

几个关键做法：

- **聊天记录标“他/我”，不标 user/assistant。** 笔记是 AI 用第一人称写的，“我”就是它自己。真实数据上复现，旧标签 3 次错 2 次，“他/我”0 次。
- **写入前机械检查。** 新笔记里出现的原话，如果聊天里只有 AI 说过、用户从没说过，就列出来让模型重写一次。不调模型，只比原话。
- **记忆带日期，模型知道今天几号。** 约好的事标月-日；过了日子没听说办没办的，改成一句“吃了没？”留着问。
- **自动改的门槛很严，其余的交给 AI 自己判断。** 校对模型大约七成准，硬改会改反。拿不准的疑点连同聊天原文附进下一次整理，“错了就改，拿不准就留着”。真实数据上 6 条疑点改对 5 条。
- **原话事实必须逐字引用**，引文不在那条消息里就丢掉，挡掉模型编造。
- **问旧事先翻再答。** 用户问“还记得……吗”，原话又不在眼前时，模型最常见的反应是“记得啊”然后往下编。给它一个翻聊天记录的工具，结果每行标好谁说的。

## 旧事怎么想起来

两条路，都按二字组的少见程度打分，不用向量：

- **片段回忆**（自动，默认开）：每轮拿用户这句话去更早的聊天里找，最多 3 段、每段带前后各一句，拼进记忆块。最近 3 小时的不找，那些还在对话历史里。
- **翻记录工具**（可选）：自动回忆只认用户这句话里的词。用户说“上次那个后来咋样了”，话里没有关键词，就搜不到。这时让 AI 自己写要找什么，或者按日期翻。记忆代理加一个配置就能开，机器人那边不用改，见 [接入指南](docs/接入.md#翻记录工具)。

真实数据上的离线测试（deepseek-flash，开思考）：把“一周后用户问起某件事”插进真实聊天，AI 翻了 11/20 次、9 次翻到；没工具时有两题她否认说过、或把谁说的弄反，有工具时答对了。日常闲聊 15 轮误翻 1 次。

### 和向量检索比

我们在一个真实陪伴 AI 的 6479 句聊天上，拿本地向量模型 bge-base-zh-v1.5 比过。挑 60 段聊天，每段造 3 种问法，看那段原话进没进前 3 / 前 6：

| 问法 | 二字组（本项目） | 向量 | 二字组 + 向量混合 |
|---|---|---|---|
| 自然问法 | 48 / 50 | 49 / 50 | 48 / 53 |
| 换说法（不用原话里的词） | 21 / 28 | 21 / 24 | 23 / 34 |
| AI 自己写的搜索词 | 53 / 54 | 54 / 54 | 56 / 57 |

效果打平；混合在前 6 多几题，60 题的样本里这点差距可能是偶然。成本差得多：

| | 二字组 | 向量（bge-base-zh-v1.5，CPU） |
|---|---|---|
| 要装的东西 | 无 | 391MB 模型 + Python/PyTorch |
| 第一次建索引 | 不用 | 给全部聊天算向量约 15 分钟 |
| 每条新消息 | 追加一行 | 再算一次向量 |
| 一次检索（6479 句） | 约 7 毫秒 | — |
| 内存 | 整个 Node 进程约 120MB | 另加一个常驻的模型进程 |

能说的是：**在一个人几个月聊天的规模上，找旧事的效果和本地向量模型差不多，资源成本接近零。** 说不了的：

- 只有一个人的数据、60 道题。问法是模型看着原文造的，会沾上原话里的词，对二字组有利。“换说法”那一行最接近真实情况，二字组和向量都只有三分之一左右。
- 没和 mem0 这类完整的检索系统（带重排、带记忆抽取）比过，也没跑公开评测。
- 检索是把全部聊天扫一遍，时间随聊天量线性增长。几十万句以后可能要分卷或换索引。
- 仓库里没带向量检索。要接的话，替换 [src/recall.mjs](src/recall.mjs) 里的打分函数 `idfScores`。

## 快速开始：不改代码，换个 API 地址就行

需要 [Node.js](https://nodejs.org) 18 以上，没有其他依赖。

1. 下载本仓库（`git clone https://github.com/moASPILyu/companion-memory.git`，或在 GitHub 页面 Code → Download ZIP）。
2. Windows 双击 `start.bat`；macOS / Linux 运行 `./start.sh`。第一次会问几个问题：原来用哪家的接口、AI 叫什么、怎么称呼用户。
3. 把机器人设置里的 **API 地址**改成 `http://127.0.0.1:8787/v1`，key 和模型名不用动。
4. 想让 AI 能自己翻聊天记录：在 `companion-memory.json` 里加 `"recallTool": true`（模型要支持工具调用）。

之后每句话都会记进流水账，每一轮自动拼上记忆，空闲时整理笔记、对账。浏览器打开 `http://127.0.0.1:8787/memory/note` 能看到她写的笔记。

能填“自定义 OpenAI 兼容地址”的机器人、聊天前端都能这么接。自己写的机器人（Python 等任何语言）也可以调几个 HTTP 接口。详见 **[接入指南](docs/接入.md)**。

### 先试试看

```bash
npm test                                   # 假模型跑全部测试，不花钱
MEMORY_LLM_KEY=你的key npm run demo         # 用合成聊天真跑一遍（默认 DeepSeek）
```

Windows PowerShell 里设环境变量：`$env:MEMORY_LLM_KEY="你的key"; npm run demo`。

## 在代码里用（Node）

```js
import { CompanionMemory } from 'companion-memory';
import { openaiLLM } from 'companion-memory/adapters/openai.mjs';

const mem = new CompanionMemory({
  dir: './memory-data',
  llm: openaiLLM({ baseUrl: 'https://api.deepseek.com', model: 'deepseek-flash' }), // key 读环境变量 MEMORY_LLM_KEY
  persona: { name: '小满', about: '你在QQ私聊里一直陪着的那个人', traits: '嘴硬、爱斗嘴' },
});

// 1. 每句话都记，双方的都要
mem.log('user', userText);
mem.log('assistant', replyText);

// 2. 回复前，把记忆块拼进这一轮的提示词——放在请求末尾，别插在历史消息前面（会让提示缓存失效）
const memoryBlock = mem.context(userText);

// 3. 空闲时调用（比如每次回复完、或每 5 分钟），到点的整理会自己跑，同一时间只跑一项
setInterval(() => mem.idle().catch(console.error), 5 * 60e3);

// 4. 可选：给模型一个翻聊天记录的工具
import { searchTool } from 'companion-memory';
tools.push(searchTool({ name: 'recall_chat' }));          // OpenAI 格式的工具定义
// 模型调用时：
const { text } = mem.search(JSON.parse(toolCall.function.arguments)); // 结果当 tool 消息喂回去
```

只想要其中一块（比如只要对账、或只要写入前检查），每个模块都能单独用，见 [src/index.mjs](src/index.mjs)。

### 常用选项

| 选项 | 默认 | 说明 |
|---|---|---|
| `persona.name` / `about` / `traits` | — | AI 叫什么、和用户什么关系、反省时不许被改掉的性格 |
| `labels` | `{user:'他', self:'我', ai:'她'}` | 笔记里怎么称呼用户；用户是女生就写 `user:'她', ai:'TA'` 之类，三个必须不同 |
| `offset` | `8` | 时区小时数，日期、周、月都按它算 |
| `features` | 全开 | 关掉某几项，比如 `{ style: false, reviews: false }` |
| `extras()` | `[]` | 对账时额外的证据，比如送礼记录（`kind:'fact'`）、AI 自己的日记（`kind:'hint'`，只当旁证） |
| `options.note.minNew` | `30` | 攒够多少句新聊天、聊天停了 10 分钟才更新笔记 |
| `options.audit.per` | `6` | 每次空闲最多对几句，聊天停了 30 分钟才开始 |
| `options.episodes` | `{max:3, skipHours:3}` | 片段回忆最多几段、最近几小时的不找；`features.episodes:false` 关掉 |
| `options.search` | `{perWindow:3, windowMs:120000, perDay:30}` | 翻记录的次数上限，防止模型每句都翻 |

## 评测

`eval/run.mjs` 用合成数据真调模型，结果在 [eval/results.md](eval/results.md)：埋了 10 处错的笔记，对账抓到几处、误报几处、疑点交回去以后改对几处。

deepseek-flash 跑 3 轮的结果：

| | 第 1 轮 | 第 2 轮 | 第 3 轮 |
|---|---|---|---|
| 对账抓到的错 | 10 / 10 | 9 / 10 | 10 / 10 |
| 误报（8 句对的） | 0 | 0 | 0 |
| 疑点交回整理后还错着 | 0 | 1 | 0 |
| 被误删的对句子 | 0 | 0 | 0 |

漏掉的那句是“初稿还没写完就先发给了导师”——先后顺序的错最难查。合成聊天只有 116 句，比真实使用简单得多，数字只说明流程跑得通，不代表真实效果。“他/我”和 user/assistant 两种标签在合成数据上都是 0 次踩坑，复现不出真实数据上 2/3 对 0/3 的差距。整套 3 轮花了 63 次调用、约 7 万输入 token、5 万输出 token。

## 局限

- 为“一个 AI 陪一个人”设计。多个人用同一个机器人时可以按人分开存（请求头 `X-Memory-User`），但群聊里多人说话会被当成同一个人。
- 笔记有长度上限（默认 2400 字），长尾的事靠原话事实、回顾、旧片段和翻记录。检索是字组匹配，不认近义词；用户换了说法、话里没有原话的词时，三分之二的情况找不到（向量也一样）。
- 提示词全是中文；换语言要改提示词和几处中文正则（说话人检查、错误分类）。
- 没跑过 LoCoMo、LongMemEval 这类公开评测。
- 对账第一次要查整份笔记，之后每周只查新写的句子；用量取决于你的模型和笔记长度。
- “自纠错”纠的是记忆内容，整理规则是人写的，不会自己变。错误统计是为下一步准备的：按反复出现的错误类型，让 AI 自己提议怎么改规则。
