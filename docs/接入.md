# 接入你的 AI

三种接法，从省事到灵活：

| 方式 | 要不要改代码 | 适合 |
|---|---|---|
| **A. 记忆代理** | 不用，改一个 API 地址 | 任何能填“自定义 OpenAI 兼容地址”的机器人、前端、插件 |
| **B. HTTP 接口** | 加三四行请求 | 自己写的机器人，Python、Go、什么语言都行 |
| **C. Node 库** | 在 Node 项目里直接调用 | 想细调每一步、只用其中几块 |

先装 [Node.js](https://nodejs.org) 18 以上（LTS 版就行）。本项目没有任何依赖，不用 `npm install`。

---

## A. 记忆代理（推荐）

```
你的机器人 ──► 记忆代理 127.0.0.1:8787 ──► 原来的模型接口（DeepSeek / OpenAI / …）
                 │ 记下用户这句、拼进记忆
                 │ 回复原样返回，同时记下 AI 的回复
                 └ 空闲时整理笔记、写回顾、对账
```

1. 下载本仓库（`git clone`，或在 GitHub 页面点 Code → Download ZIP 解压）。
2. 启动：
   - Windows：双击 `start.bat`
   - macOS / Linux：终端里运行 `./start.sh`

   第一次会问几个问题（原来用哪家接口、整理记忆用哪个模型、AI 叫什么、怎么称呼用户），生成 `companion-memory.json`。以后再启动直接开跑。
3. 在你的机器人设置里，把 **API 地址（base_url / API Base / 接口地址）** 改成启动时打印的地址，默认是：

   ```
   http://127.0.0.1:8787/v1
   ```

   **key 和模型名都不用改。** 代理会把请求原样转给原来的接口，只在最后一条用户消息前面加一段 `<memory>…</memory>`。

能填自定义 OpenAI 兼容地址的都能这么接，比如各类 QQ / 微信 / Discord 机器人框架的 OpenAI 模型设置、SillyTavern 的 Chat Completion 自定义接口、各种聊天客户端。具体在哪个菜单，看那个软件的文档里“自定义 API 地址 / OpenAI 兼容”一项。

### 整理记忆用的 key

整理（写笔记、对账）要单独调模型。两种给法：

- 什么都不设：代理会借用机器人请求里带的那把 key，只放在内存里，不写进任何文件。代理重启后，要等机器人说第一句话才有 key。
- 设 `MEMORY_LLM_KEY`：整理改用这把 key（比如想用另一家更便宜的模型整理，再在配置里改 `organizer.baseUrl` 和 `organizer.model`）。第一次启动时的问答可以直接填，会存进本目录的 `.env`（只在本机，不会提交到 git）；也可以自己设环境变量，环境变量优先。

用下面的 HTTP 接口时，机器人不经过代理，借不到 key，**一定要设**。

### 配置文件 `companion-memory.json`

| 字段 | 说明 |
|---|---|
| `upstream` | 机器人原来调的接口地址 |
| `port` / `host` | 代理监听的端口和地址，默认 `127.0.0.1:8787`。**没有密码，不要改成 0.0.0.0 暴露到公网** |
| `organizer.model` | 整理记忆用的模型；`organizer.baseUrl` 不填就用 `upstream` |
| `persona` | `name` AI 的名字、`about` 和用户的关系、`traits` 反省说话习惯时不许改掉的性格 |
| `labels` | 笔记里的称呼，`user` 用户、`ai` AI 的第三人称，两个必须不同 |
| `inject` | `user`（默认，记忆拼在最后一条用户消息前）或 `system`（在它前面插一条 system 消息） |
| `idleMinutes` | 隔几分钟检查一次要不要整理，默认 5 |
| `dataDir` | 数据目录，默认 `./memory-data` |

### 几种特殊情况

- **重新生成 / 换一条回复**：同样的历史再发一遍时，用户那句不会重复记，新回复标 `regen`。
- **机器人自己的内部请求**（起标题、做总结之类）：请求头带 `X-Memory: off` 就原样转发、不记不拼。
- **多个人用同一个机器人**：请求头带 `X-Memory-User: 名字`（或请求体里的 `user` 字段），每人一个数据目录。不带就都算 `default`。
- **群聊**：这套记忆按“一个 AI 陪一个人”设计，群里多人说话会被当成同一个人记。
- **思考模型**：回复里的 `<think>…</think>` 不会记进流水账。

看笔记：浏览器打开 `http://127.0.0.1:8787/memory/note`。

### 接 QQ（微信、Discord 同理）

QQ 机器人一般是三层，记忆代理插在后两层之间：

```
QQ ⇄ 协议端（NapCat、LLOneBot 等，登录 QQ、收发消息）
        ⇄ 机器人框架（AstrBot、NoneBot、Koishi、LangBot 等，决定怎么回、调模型）
              ⇄ 记忆代理 ⇄ 模型接口
```

协议端不用动，只在**机器人框架的模型提供商设置**里，把 API 地址（API Base / base_url）改成代理地址。

几点要注意：

- **最适合私聊、一个人。** 框架一般不会告诉代理“这句是谁说的”，群聊或多人私聊都会混在一起记。如果框架能给不同会话配不同的模型提供商，就只让你和她的私聊走代理；要按 QQ 号分开记，用下面的 HTTP 接口在插件里传 `user`。
- **框架自己的后台请求也会经过代理。** 比如框架自带的长期记忆、对话总结、起标题，会被当成用户说的话记进去。建议关掉框架自带的记忆和总结（和这套重复），或者给这类功能单独配一个不经过代理的提供商。
- 工具调用（查天气、搜索之类）的后续请求算同一轮，用户那句只记一次，只记最后的文字回复。

## B. HTTP 接口

先按 A 的第 1、2 步把服务启动起来（不用改机器人的 API 地址），然后在你的代码里：

1. 每句话都记：`POST /memory/log`，`{"role": "user" | "assistant", "text": "…"}`
2. 回复前取记忆块，拼进这一轮的提示词：`POST /memory/context`，`{"query": "用户这句话"}` → `{"context": "…"}`
3. 整理会自己定时跑；想手动触发：`POST /memory/idle`

都可以加 `"user": "名字"` 区分不同的人。

Python 例子：

```python
import requests
MEM = "http://127.0.0.1:8787/memory"

def reply(user_text, history):
    requests.post(f"{MEM}/log", json={"role": "user", "text": user_text})
    memory = requests.post(f"{MEM}/context", json={"query": user_text}).json()["context"]
    messages = history + [{"role": "user", "content": f"<memory>\n{memory}\n</memory>\n\n{user_text}"}]
    answer = call_your_model(messages)          # 你原来调模型的代码
    requests.post(f"{MEM}/log", json={"role": "assistant", "text": answer})
    return answer
```

记忆块要拼在**这一轮**（最后一条用户消息）里，不要写进固定的系统提示词开头：它每轮都会变，放在历史前面会让提示缓存失效，费用翻好几倍。

其他接口：`GET /memory/note` 笔记全文，`GET /memory/status` 条数和最近的整理事件。

## 常用命令

```bash
node bin/companion-memory.mjs            # 启动（第一次先问问题）
node bin/companion-memory.mjs init       # 重新生成配置
node bin/companion-memory.mjs note       # 看笔记
node bin/companion-memory.mjs audit      # 马上对账一次（要在 .env 或环境变量里设 MEMORY_LLM_KEY）
node bin/companion-memory.mjs note --user alice   # 看某个人的
```

## 出问题先看

- `memory-data/<user>/events.jsonl`：每一步整理做了什么、为什么没做、哪里失败。
- 笔记一直没出来：攒够 30 句新聊天、聊天停了 10 分钟才写第一版。
- `端口被占用`：改配置里的 `port`，机器人那边的地址跟着改。
- 机器人报 502：代理连不上原来的接口，检查 `upstream` 和网络。
